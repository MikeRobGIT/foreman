# foreman 0.5.1: spec-phase fixes from the dry runs — design

Status: draft for review (2026-10-04). Branch `feat/spec-phase-fixes`, stacked on `feat/spec-phase` (0.5.0, PR #3).

## Purpose

The 0.5.0 dry runs (PR #3's description, scenarios A, A′, B, C, D) found 15 problems. The spec phase worked, but
the orchestrator skipped two tables it was told to show, asked one invalid question, used blocked or misused
harness tools, and kept state only in its own context, so the status band and the tables had nothing reliable to
read. 0.5.1 fixes all 15.

Success means:
- the W3.6 checkpoint table and the W6 spec-phase table appear in every run that has a spec phase;
- a Release question can't be asked before the checkpoint table was shown for the current state (manual mode,
  hooks active);
- every batch that reaches the spec phase ends `released` or `parked` with a reason from a closed list, including
  a batch whose worker the human stopped;
- no foreground `sleep`, no TaskStop without a recorded task id, no idle reviewer teammate holding a PTY;
- workers can commit in a worktree when an RTK-style git rewrite hook is installed;
- the status band shows one prefix and counts that match the batch state.

## Decisions (from brainstorming, 2026-10-04)

- **Ambiguous rows: the spec phase owns them.** W2 stops filtering "needs a human decision" in parallel mode. A
  batch whose spec has a blocking open question parks at `SPEC READY`, before any review round.
- **Tables: state file + script + hook.** Batch state moves out of the orchestrator's context into one JSON file
  per batch, written by a new `scripts/batches.py`. The tables are printed by that script, and a hook denies the
  Release question until the checkpoint table was printed for the current state.
- **A human stop parks the batch** with the new reason `stopped by the human`. The worker isn't resumed or
  relaunched.

## Non-goals

- Serial mode, W2's batching, W4's build-phase checks and the reviewer chain are unchanged.
- No new reviewer adapters. Codex being out of credits is an account problem, not a foreman bug; finding 14 only
  makes the weaker review visible.
- Finding 15 (bypass mode hides the missing `permissions.allow` entries) needs no change: W3 already warns on every
  run, and bypass mode is the user's choice.

## Components

### 1. `scripts/batches.py`: batch state on disk

The source of truth for the spec-phase tables, the checkpoint gate and the status band. Pure Python 3 stdlib, like
the other scripts. It never calls git or gh.

**Location.** One JSON file per batch, `<state dir>/batches/<session>/<batch>.json`, next to the hooks' existing
`<batch>.released` and `<batch>.stopped` records. `<state dir>` is `state.state_dir(main)` (`$FOREMAN_HOME`,
default `~/.claude/foreman`, then the repo key). `<session>` is resolved in this order:
1. `$FOREMAN_SESSION`, exported for every Bash call by a new `SessionStart` hook (`hooks.py session-start` writes
   `export FOREMAN_SESSION=<session_id>` to `$CLAUDE_ENV_FILE`). Probe P1 confirms the mechanism before the code
   relies on it.
2. Else the session of the only live run marker in the state dir.
3. Else `nosession`: the tables still work; the gate and the status band (which need a marker) see nothing.

Two live markers and no `$FOREMAN_SESSION` → exit 1, "two live foreman runs in this repo; can't tell which is
yours".

**Fields.** Unknown keys are refused.

| key | meaning |
|---|---|
| `status` | `spec`, `review <r>`, `passed`, `released`, `PR #<n>`, or `parked: <reason>` |
| `rows`, `owned` | comma-separated row ids, comma-separated owned files |
| `worktree`, `branch`, `spec`, `fork_base` | from W3 and the first `SPEC READY` |
| `sha` | the SHA the current round is pinned to (each `SPEC READY`) |
| `reviewed_sha`, `released_sha`, `verified_sha` | at pass, at release, at W4.1 |
| `pr`, `pr_rounds` | PR number; review rounds after the PR opened (W4.4 sends) |
| `worker_task`, `timer_task`, `chain_task`, `reviewer_task` | task ids from the Agent / Bash results; the only ids TaskStop may take |
| `reviewer_model` | the read-only reviewer's model (W3.5 step 8) |
| `degraded` | `yes` or `no` |
| `minors`, `questions` | the open Minor findings and open questions, one line each, `;`-separated |
| `park_note` | the park's detail for W5's row note |

Clock stamps are lists, appended by `stamp`: `sent`, `spec_ready`, `stopped` (epoch seconds). Rounds are a list
appended by `add-round`: `{r, sha, chain, fallthrough, explore, crit, imp, minor}`.

**CLI.** Every command exits 0 on success and 1 with a one-line reason on stderr; usage errors exit 2.

| command | does |
|---|---|
| `set <batch> key=value…` | creates the file on first use; sets the keys |
| `stamp <batch> sent\|spec_ready\|stopped [<epoch>]` | appends a clock stamp (default now) |
| `add-round <batch> r=<n> sha=<sha> chain=<reviewer\|none> [fallthrough=<why>] explore=<pass\|revise\|none> crit=<n> imp=<n> minor=<n>` | appends a round; sets `status=review <n>` |
| `show [<batch>] [--json]` | one batch, or every batch of the session; adds computed `worker_time` and `remaining` (against `spec_phase_timeout`) |
| `table checkpoint <wave>` | prints the W3.6 table for the wave's batches and writes the wave's shown-stamp |
| `table report` | prints the W6 spec-phase table for every batch of the session |

`<wave>` is a batch name minus its final letter (`20261002-1530-w1` for `20261002-1530-w1a`).

**Status validation.** `parked: <reason>` takes a reason from this closed list (W3.5's bounds table plus the new
one); anything else is refused:
`open question` · `no pass in <n> rounds` · `spec phase timed out` · `spec incomplete` ·
`spec incomplete after 2 bounces` · `review could not run` · `worker stuck` · `not released by the human` ·
`scope conflict` · `release could not be recorded` · `stopped by the human`.

**Writes** are atomic: a temp file in the same directory, then `os.replace`. A file that doesn't parse as JSON is
refused (exit 1, "corrupt batch state: <path>"), never overwritten.

**Tables.**
- `table checkpoint <wave>` columns: batch, rows, spec path, rounds, chain reviewer (`⚠ degraded` when
  `degraded=yes`), last read-only verdict, open Minor findings, open questions, status. It then writes
  `<state dir>/batches/<session>/<wave>.shown` = `{at, digest}`, where `digest` is the SHA-1 of the wave's sorted
  `batch=status` lines.
- `table report` columns: batch, spec wall-clock (first `sent` to release or park), rounds, landed reviewer (or the
  fall-through, or `no cross-model review`), reviewer model, park reason, rounds after the PR (`pr_rounds`).

### 2. Hook piece 11, `batch_state`

In `scripts/hooks.py`, run-only (needs this session's run marker), with three duties:
1. **Worker deny** (Bash, any tagged or untagged subagent): a call that runs `batches.py` is denied, "only the
   orchestrator writes batch state". Detection reuses `runs_control`'s shape (a word naming `batches.py` as a
   command, including inside a shell or eval script), so a mention in a string or heredoc isn't a call.
2. **Checkpoint gate** (`AskUserQuestion`, main session only). When any question's `header` is exactly
   `Release`, find the waves of this session's batch files that have a `passed` batch. For each, deny when
   `<wave>.shown` is missing, or its digest differs from the current digest. The deny reason names the command:
   "show the checkpoint table first: python3 $FOREMAN/batches.py table checkpoint <wave>". Other questions pass
   untouched.
3. **Fail open.** Its own error (unreadable state, bad JSON in a batch file) prints a stderr note and allows the
   call, like every piece. Only a definite missing or stale stamp denies.

`hooks/hooks.json` gains a `PreToolUse` entry with `"matcher": "AskUserQuestion"` and a `SessionStart` entry for
`session-start`. `hooks_disabled: [batch_state]` turns the piece off; `session-start` is not a piece and always
runs.

### 3. The status mod reads the batch files

`hooks/status.mjs`:
- `summary()` returns the text without `foreman: `; the harness already prefixes the plugin's status line.
- `collect()` first runs `python3 <root>/scripts/batches.py show --json` (with the session id as
  `FOREMAN_SESSION`). With batch files, there is one line per batch: name, status, round, PR, and for a batch
  with a PR the existing CI, bots, threads and merge cells. The summary reads
  `<n> batches · <s> spec · <p> passed · <r> released · <k> parked · <m> PRs · <g> green`, leaving out zero
  counts.
- With no batch files for the session (serial runs, pre-0.5.1 runs), it falls back to today's worktree scan.

### 4. SKILL.md changes

- **W2:** the pool filter "need a human decision" is dropped in parallel mode; the parked-row rule stays.
- **W3:**
  - The state table bullet is replaced by `batches.py`: at launch,
    `batches.py set <b> status=spec rows=… owned=… worktree=… branch=… worker_task=<id>`, then `stamp <b> sent`.
  - The preflight also warns when a `PreToolUse` Bash hook in `~/.claude/settings.json`, `.claude/settings.json`
    or `.claude/settings.local.json` has a command mentioning `rtk`.
  - The prompt carries `GIT=<absolute path of git>` (resolved with `command -v git` before launch).
- **W3.5:**
  - Step 1 (pre-checks): an Open questions line starting `- **Blocking:**` parks the batch now
    (`parked: open question`), before any round.
  - Step 2: reviewers are dispatched **unnamed** (no `name`: an unnamed Agent runs in-process and holds no PTY).
    Each one is TaskStopped by its recorded id as soon as its verdict lands.
  - After each round: `batches.py add-round …`. At pass:
    `set <b> status=passed reviewed_sha=<sha> degraded=<yes|no>`; `degraded=yes` when the chain landed below its
    first `reviewers` entry or not at all.
  - The orchestrator never edits a worker's spec, before or after a pass. Minor findings go in the release message
    (and from there into the PR body).
  - Step 5 (a stop without `SPEC READY`): when the stop notification, or a refused resume, says the agent was
    stopped by the user, park `stopped by the human` (the clock stays stopped; no resume). Any other stop keeps
    today's "resume once, then park `spec incomplete`".
  - Step 7 (the clock): every timer is a `run_in_background` `sleep`, never a foreground one, and its task id goes
    in `timer_task`. TaskStop takes only an id recorded in the batch file, never a batch name.
- **W3.6:**
  - **Checkpoint:** run `python3 $FOREMAN/batches.py table checkpoint <wave>` and show its output, then ask with
    `header: "Release"`. One batch: a single-select question with Release, Comment and Park. Two to four:
    today's multi-select. More than four: several `Release` questions of up to four, or a text answer.
  - The question's description repeats the degraded flag for a degraded batch.
  - **Releasing:** after `hooks.py release` succeeds, `set <b> status=released released_sha=<sha>`.
  - **Parking:**
    - The order is: kill the chain via `<log>.pid`; wait for the pid file with a `Monitor` until-loop, or a
      background `for` loop of `sleep 2`, at most 30 s; run `hooks.py stopping <batch>`; then TaskStop
      `chain_task`, `reviewer_task`, `worker_task` and `timer_task`, by their recorded ids.
    - The spec copy is taken at the last pinned SHA (`git show <sha>:<spec path>`). Only a batch with no
      `SPEC READY` yet copies from the working tree.
    - Then `set <b> "status=parked: <reason>" park_note=…`.
- **W4:**
  - On the PR: `set <b> "status=PR #<n>" pr=<n>`.
  - W4.4 increments `pr_rounds`.
  - **W4.2b:** a dispatch that fails with an environment error (`fork failed`, `Device not configured`) gets one
    more try after stopping idle teammates (ListAgents, then TaskStop by id). This retry doesn't count as the one
    re-dispatch.
- **W6:**
  - The stuck-worker rule names the recorded `worker_task` for TaskStop, after `stopping`.
  - **Run report:** paste `python3 $FOREMAN/batches.py table report` as the spec-phase table.
- **Worker contract:** run git as `$GIT` (the absolute path in your prompt), never a bare `git`. A git rewrite
  hook such as RTK turns `git` into another command, and the harness's worktree guard refuses that. `gh` is
  unchanged.
- **Hooks section:** add the piece 11 row: `batch_state`, run-only, worker deny plus checkpoint gate.

### 5. Templates

- **`templates/spec.md`**, Open questions: each entry starts `- **Blocking:**` (the batch can't be built without
  the answer) or `- **Non-blocking:**`; the placeholder says so.
- **`templates/foreman.config.md`:** `forbid_trailers: [Co-Authored-By, Claude-Session, "/Generated with/"]`, with
  a comment: "empty this list to allow attribution lines". `cfg.py`'s default stays `[]`, so existing configs
  behave as before.

## Data flow

Each step writes state; the tables, the gate and the status band only read it.

| step | orchestrator action | `batches.py` write |
|---|---|---|
| W3 launch | Agent call (first line `foreman-worker: <b> spec-phase`) | `set <b> status=spec rows=… owned=… worktree=… branch=… worker_task=<id>`; `stamp <b> sent`; `set <b> timer_task=<id>` |
| `SPEC READY` | pre-checks | `stamp <b> spec_ready`; `set <b> spec=<path> sha=<sha> [fork_base=<sha>]`; a blocking open question → `set <b> "status=parked: open question"`, park now |
| W3.5 round r | chain + read-only reviewer (unnamed) | `set <b> chain_task=<id> reviewer_task=<id>`; on the verdict, `add-round <b> r=<r> …`; reviewers TaskStopped |
| revise | findings sent | `stamp <b> sent`; `set <b> timer_task=<id>` |
| pass | — | `set <b> status=passed reviewed_sha=<sha> degraded=<yes\|no> minors=… questions=…` |
| W3.6 manual | `table checkpoint <wave>`, then the Release question | the gate checks `<wave>.shown` |
| release | `hooks.py release <b> <sha>`, then the message | `set <b> status=released released_sha=<sha>` |
| park | kill, `stopping`, TaskStop by id, copy at the pinned SHA | `set <b> "status=parked: <reason>" park_note=…` |
| human stop | the stop notification, or a refused resume naming the user | `stamp <b> stopped`; `set <b> "status=parked: stopped by the human"` |
| W4 PR | — | `set <b> "status=PR #<n>" pr=<n>`; `pr_rounds` at each W4.4 send |
| W6 stop | `table report` pasted into the run report | — |

## Error handling

- **`batches.py` failures** exit non-zero with the reason (no state dir, a bad key, a status or park reason outside
  the lists, corrupt JSON, an ambiguous session). SKILL.md tells the orchestrator to fix the command and run it
  again; it never drops a state change.
- **The gate fails open** on its own errors. With no run marker, nothing is gated, but W3.6 still says to run
  `table checkpoint`.
- **The status band** falls back to the worktree scan when `batches.py` finds no files or exits non-zero; on
  `nosession` files it shows nothing new.
- **Human-stop detection is conservative.** Only the stop notification or a refused resume that names the user
  counts.
- **The degraded flag** is informational and never blocks.
