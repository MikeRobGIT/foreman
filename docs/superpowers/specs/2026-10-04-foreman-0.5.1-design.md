# foreman 0.5.1: spec-phase fixes from the dry runs — design

Status: draft for review, revision 6 (2026-10-04). Rounds 1 to 5 (three opus reviewers each: coverage, code
consistency, feasibility) returned findings; this revision answers all five (see Review responses).
Branch `feat/spec-phase-fixes`, stacked on `feat/spec-phase` (0.5.0, PR #3).

## Purpose

The 0.5.0 dry runs (PR #3's description, scenarios A, A′, B, C, D) found 15 problems. The spec phase worked, but
the orchestrator skipped two tables it was told to show, asked one invalid question, used blocked or misused
harness tools, and kept state only in its own context, so the status band and the tables had nothing reliable to
read. 0.5.1 fixes all 15.

The lesson behind the design: every finding that depended on the orchestrator following a prose step (show a
table, stop by id, stop in order, don't edit) was violated at least once. So each fix that can be enforced at a
tool call is enforced there, by a hook reading state on disk; prose is kept only where no tool call exists.

Success means:
- in manual mode, an `AskUserQuestion` at the checkpoint can't be asked, and a batch can't be released, until the
  checkpoint table for the current state is in the orchestrator's visible text; and `run-end` can't run until the
  spec-phase report table is (hooks active). The text-answer path for more than sixteen batches relies on prose;
  it is reachable only with `parallel_max` above 16;
- every batch that reaches the spec phase ends `released` or `parked` with a reason from a closed list, including
  a batch whose worker the human stopped;
- TaskStop is refused without a task id, with a batch name, and for a worker before `hooks.py stopping`;
- no foreground `sleep`, and no reviewer agent left holding a PTY after its verdict;
- workers commit in their worktrees when an RTK-style git rewrite hook is installed (decided by probe P2);
- the status band shows one prefix and counts that match the batch state;
- in `--auto-merge` (no checkpoint), a degraded review is visible in the report table.

## Decisions (from brainstorming, 2026-10-04)

- **Ambiguous rows: the spec phase owns them.** W2 stops filtering "needs a human decision" in parallel mode. A
  batch whose spec has a blocking open question parks at `SPEC READY`, before any review round.
- **Tables: state file + script + hook.** Batch state moves out of the orchestrator's context into one JSON file
  per batch, written by a new `scripts/batches.py`. The script prints the tables, and hooks refuse the checkpoint
  question and `run-end` until the matching table is in the orchestrator's visible text.
- **A human stop parks the batch** with the new reason `stopped by the human`. The worker isn't resumed or
  relaunched, and the rows stay out of later pools until the human edits the note.

## Non-goals

- Serial mode, W2's batching, W4's build-phase checks and the reviewer chain are unchanged.
- No new reviewer adapters. Codex being out of credits is an account problem; finding 14 only makes the weaker
  review visible.
- Finding 15 (bypass mode hides the missing `permissions.allow` entries) needs no change: W3 already warns on every
  run, and bypass mode is the user's choice.
- Existing configs keep their `forbid_trailers`; vacancy-vibe gets the new default in its switch-over PR.

## Components

### 1. `scripts/batches.py`: batch state on disk

The source of truth for the spec-phase tables, the hook gates and the status band. Pure Python 3 stdlib, like the
other scripts; it reads config through `cfg.py`, calls git only through `state.py` to find the state dirs, and
never calls gh.

**Location.** `<state dir>/batches/<session>/state/<batch>.json`. The `state/` subdirectory keeps the files out of
reach of `hooks.py forget` (which deletes `batches/<session>/<batch>.*`) so the report table at W6 still sees every
wave's batches. `prune` ages `batches/*/state/*` out after 14 days like the other batch files. Writes go to every
`state.state_dirs(main)` entry, as `mint` does, so a hook whose environment lacks a Bash-only `FOREMAN_HOME` still
reads them; reads take the newest copy by mtime across the dirs. Config is read with `use_env=False`, as the hooks read it,
so the script and the hooks render the same tables (`cfg.chain` gains that parameter).

**Run scope.** A session can hold several runs (`/loop` re-fires `/foreman` in the same session). The tables, the
gates and the status band consider only the current run's batches: those whose name time (`hooks.batch_time`) is at
or after the live run marker's `started`, floored to the minute (batch names have minute precision). With no live
marker, `show` and the tables cover the whole session.

**Session.** Resolved in this order:
1. `--session <id>` (the status mod passes this).
2. `$FOREMAN_SESSION`, exported for every Bash call by a new `SessionStart` hook: `hooks.py session-start`
   appends `export FOREMAN_SESSION=<session_id>` to `$CLAUDE_ENV_FILE`, and writes nothing when it is unset.
   Probe P1 confirms the mechanism first.
3. The most recently touched live run marker in the state dirs (pushes, merges, `hooks.py` control calls and
   every `batches.py` call touch it; piece 11 does the last), with a stderr note naming the session when there
   are two or more.
4. Else `nosession`: the tables still work; the gates and the status band (which need a marker) see nothing.

**Locking.** Every read-modify-write, and every table render with its stamp, runs under an exclusive `fcntl.flock`
on `batches/<session>/state/.lock` in the first state dir. Writes are atomic: the temp files for every state dir
are written first, then each is moved into place with `os.replace`. If a later dir fails after the first has been
replaced, the command exits 0 with a stderr note naming the dir, so a retry never applies a `stamp` or `bump`
twice. Readers (the hooks, `show`) take the newest copy by mtime across the state dirs, so a dir left behind by
a partial write is never read as current. A file that doesn't parse as JSON is refused (exit 1, "corrupt batch state: <path>") and left untouched.

**Argument syntax.** Every argument is one shell word with no quotes, spaces, `;` or `$`, so piece 8 can allow
the calls without a prompt. Free text (Minor findings, open questions, a park note) is read from a file with
`note`, never from the command line.

**Fields.** Unknown keys and values outside the listed tokens are refused.

| key | values |
|---|---|
| `status` | `spec`, `review`, `passed`, `released`, `pr`, `parked` (the round number comes from `rounds`, the PR number from `pr`) |
| `reason` | with `status=parked` only, one of: `open-question`, `no-pass`, `timed-out`, `spec-incomplete`, `bounces`, `review-failed`, `worker-stuck`, `not-released`, `scope-conflict`, `release-unrecorded`, `stopped-by-human`, `comment-failed` |
| `rows`, `owned` | comma-separated row ids / owned files |
| `worktree`, `branch`, `spec`, `fork_base` | from the first `SPEC READY` (never set at launch) |
| `sha` | the SHA the current round is pinned to |
| `reviewed_sha`, `released_sha`, `verified_sha` | at pass, at release, at W4.1 |
| `pr` | PR number |
| `reviewer_model` | W3.5 step 8's model |

Counters: `pr_rounds` (W4.4 sends after the PR opened), `bounces`. Text fields, set by `note`: `minors`,
`questions`, `park_note`. Computed, never set: `degraded`, `worker_time`, `remaining`.

Reasons render as prose in tables and W5 notes: `open-question` → "open question", `no-pass` → "no pass in <n>
rounds", `timed-out` → "spec phase timed out", `spec-incomplete` → "spec incomplete", `bounces` → "spec incomplete
after 2 bounces", `review-failed` → "review could not run", `worker-stuck` → "worker stuck", `not-released` → "not
released by the human", `scope-conflict` → "scope conflict", `release-unrecorded` → "release could not be
recorded", `stopped-by-human` → "stopped by the human", `comment-failed` → "comment round failed".

**Stamps** (epoch seconds, appended): `sent`, `comment_sent`, `spec_ready`, `stopped`. `passed` is appended
automatically when `status` becomes `passed`, and `ended` when it becomes `released` or `parked`. Worker time is the sum of each `spec_ready` or
`stopped` minus the `sent` before it, plus `now − last sent` while working; intervals opened by `comment_sent`
are left out (W3.5's clock rule).

**Tasks.** A list of `{kind, id, added, verdict, live}` entries, `kind` one of `worker`, `timer`, `chain`,
`reviewer`; `added` is the time of `task add`. Several of a kind can be live at once (two reviewers in W3.5 case c,
a timer per running reviewer, W4.2b's reviewer). These ids are the only ones TaskStop is given for a batch. The id
is what TaskStop accepts:
- a worker: its agent name, which W3 sets to `fw-<batch>` (never the bare batch name);
- an unnamed reviewer: the agent id in the Agent result;
- a background Bash task (timer, chain): the task id in its result.

**Rounds.** A list appended by `add-round`: `{r, sha, entry, fallthrough, explore, crit, imp, minor}`. `degraded`
is `yes` when the last round's `entry` is `0`, or isn't the first `cfg.chain` entry whose adapter carries the
`# foreman: reads-repo` marker and, for `custom`, has both `{prompt_file}` and `{base}` placeholders, as custom.sh
requires in spec mode (the first one eligible in spec mode). An empty or wholly ineligible chain is always
degraded. Entries are compared by position, so a fall-through to a second entry of the same adapter counts.

**CLI.** Exit 0 on success, 1 with a one-line reason on stderr, 2 on a usage error.

| command | does |
|---|---|
| `set <batch> key=value…` | creates the file on first use; sets the keys. `status=passed` needs `reviewed_sha` in the same call; `status=released` is refused unless `released_sha` equals `reviewed_sha`; `status=parked` needs `reason` |
| `note <batch> minors\|questions\|park_note <file>` | sets the text field to the file's non-empty lines |
| `bump <batch> pr_rounds\|bounces` | adds one |
| `stamp <batch> sent\|comment_sent\|spec_ready\|stopped` | appends now; `comment_sent` also sets `status=review` and clears `reviewed_sha` |
| `task <batch> add <kind> <id>` / `verdict <id>` / `done <id>` | records a task / marks its verdict landed / marks it not live |
| `add-round <batch> r=<n> sha=<sha> entry=<n> [fallthrough=<adapter:why,…>] explore=<pass\|revise\|none> crit=<n> imp=<n> minor=<n>` | appends a round; `entry` is the 1-based position in `cfg.chain` of the reviewer that landed, `0` for none (read from `<log>.entry`, which review.sh 0.5.1 writes); `why` is one of `error`, `quota`, `reads-repo`, `timeout`, `missing` |
| `show [<batch>] [--json] [--session <id>]` | one batch, or every batch of the session, with the computed fields |
| `table checkpoint <wave>` | prints the W3.6 table for the wave and writes its stamp |
| `table report` | prints the W6 spec-phase table for the current run (the whole session with no live marker) and writes its stamp |

`<wave>` is a batch name minus its final letter (`20261002-1530-w1` for `20261002-1530-w1a`).

**Tables.** Both print a first line `foreman <checkpoint|report> <wave|session> <id>`, where `<id>` is the first
8 hex digits of the SHA-1 of the rendered rows, then a Markdown table. No cell depends on the current time: an
unfinished value renders `—`, so re-rendering unchanged state gives the same text. A text field becomes one cell:
its lines joined with `; `, `|` escaped as `\|`, at most three items, then `+<n> more (batches.py show <b>)`.
- `table checkpoint <wave>`: batch, rows, spec path, rounds, chain reviewer (`⚠ degraded` when degraded), last
  read-only verdict, open Minor findings, open questions, status. Stamp:
  `batches/<session>/state/<wave>.shown` = `{at, id, text}`.
- `table report` (the current run; the whole session with no live marker): batch, spec wall-clock (first `sent` to `ended`, `—` with no `ended`), rounds, landed reviewer (or the fall-through,
  or `no cross-model review`), degraded, reviewer model, status and park reason, rounds after the PR. Stamp:
  `batches/<session>/state/report.shown`.

Because the id hashes the whole rendered table (status, round count, verdict, Minor findings, questions), a comment
round that ends `passed` again still changes it (scenario A′).

### 2. Hook piece 11, `batch_state`

In `scripts/hooks.py`, run-only, main session unless noted. `hooks_disabled: [batch_state]` turns it off. Every
duty fails open on its own errors (stderr note, allow), like every piece.

1. **Worker deny** (Bash, any subagent). A call that runs `batches.py` is denied: "only the orchestrator writes
   batch state". `FAST` gains `batches\.py` so the Bash pieces see the call; detection reuses `runs_control`'s
   shape, so a mention in a string or heredoc isn't a call. A main-session `batches.py` call touches the run marker.
2. **Checkpoint gate** (`AskUserQuestion`). It applies at the checkpoint moment: some wave of the current run has
   at least one `passed` batch and none in `spec` or `review` (`released`, `pr` and `parked` count as settled, as does a
   batch with a hooks.py `.released` record whose `set status=released` was skipped, so a follow-up checkpoint after a comment round in a mixed wave is gated too). (In `--auto-merge` a batch is released as soon as it
   passes, so a wave is never in that state for long; while other batches are still in review, questions aren't
   gated.) Then every `AskUserQuestion` is checked: for each such wave, the current rendered table must equal the
   stamp's `text`, and every line of it must appear in the assistant text blocks of `transcript_path` written
   after the stamp's `at`. Lines are compared with all whitespace removed, so re-padded cells and `| --- |` match.
   A Bash tool result doesn't count: the table must be in the orchestrator's own text, which the human sees.
   Every piece-11 deny text gives commands with the resolved script path (`HERE`, as pieces 1 and 3 do, since
   `$FOREMAN` isn't set in Bash), shown here as `<path>`: "run `python3 <path>/batches.py table checkpoint <wave>` and paste its output as text before
   asking", or "the table changed since it was shown; run it again". After two denies against one unchanged
   rendered table, the third question is allowed with a stderr note. Every deny names `hooks_disabled:
   [batch_state]` as the way out.
3. **Report gate** (`run-end`). Tested with `ends_run(sc)`, the predicate posttool uses to delete the marker, in
   `pretool_bash` before the control-call branch, so `run-end 2>&1` and `cd <dir> && python3 ./hooks.py run-end`
   are gated too. When the current run has batch files, `run-end` is denied until `report.shown` exists, its text
   equals the current rendered report, and its lines are in the assistant text after its `at`: "paste
   `python3 <path>/batches.py table report` into the run report first". It can't trap the session: after two
   denies against the same rendered report, the third `run-end` is allowed with a stderr note, and every deny names
   `hooks_disabled: [batch_state]` as the way out.
4. **TaskStop guard** (`TaskStop`; the id is `task_id`, else the deprecated `shell_id`, with any `@<team>` suffix
   removed). `fw-<batch>` and `fw-<batch>-<k>` for a batch of the current run, and an agent id whose agent-map entry is a
   tagged worker of such a batch, count as worker ids even when no `task add` recorded them; for those, any
   `.stopped` record suffices. "The `.stopped` record" is always hooks.py's `batches/<session>/<batch>.stopped`,
   never the batches.py `stopped` stamp. Deny when the id is
   missing or empty; when it equals a batch name of the current run and no batch records it as a task id
   ("TaskStop takes a task id, not a batch name; the ids are in `python3 <path>/batches.py show <batch>`"); or when it is a live
   `worker` task of a batch whose `<batch>.stopped` record is missing or older than the task's `added` ("run
   `python3 <path>/hooks.py stopping <batch>` first"). An id no batch records is allowed: the session has other
   tasks.
5. **Release check**, inside `pretool_bash`'s control-call branch, before `pretool_control` records anything:
   when the verb is `release` and piece 11 is active, the call is denied (nothing recorded) when:
   - the batch's state file exists and its `status` isn't `passed`, or its `reviewed_sha` is unset or isn't `<sha>`
     ("release only a passed batch at its reviewed SHA <sha>; a spec that changed after review needs a new round");
   - the run is manual (the marker's args have no `--auto-merge` or `loop`) and no `<wave>.shown` stamp whose `at`
     is after the batch's latest `passed` stamp lists it as `passed` with its lines pasted after the stamp's `at` ("show the
     checkpoint table first"). The stamp needn't equal the current table, since a release changes it;
   - there is no state file but the agent map holds a spec-phase worker for the batch ("record the batch with
     `python3 <path>/batches.py set` first").

   With no state file and no such worker it is allowed. Duty 5 has no escape (a wrong release can't be undone),
   but every deny names `hooks_disabled: [batch_state]`.

**Deny counts** for the escapes in duties 2 and 3 live in `batches/<session>/state/<wave>.denies` and
`report.denies` (`{id, count}`), written by the hook and reset when the rendered table's id changes.

Reading the transcript: from the end backwards, stopping at the first entry older than the stamp's `at` (floored to
the second, to match the transcript's ISO timestamps), so a long run's transcript stays inside the hook timeout.

If probe P3 shows the assistant text isn't yet in the transcript when the hook fires:
- Duty 2 instead returns `updatedInput` with the stamp's table prepended to the first question's text, if P3 also
  shows that a question changed this way still opens the dialog and returns the human's answer. If it doesn't, duty
  2 denies with "put the checkpoint table in your text before asking", relying on the same escape.
- Duty 3 instead accepts the report pasted in an earlier assistant message. W6 then pastes the report, makes one
  more call (`batches.py show`), and runs `run-end`.

`pretool()` gains `AskUserQuestion` and `TaskStop` branches. `hooks/hooks.json` gains
`{"matcher": "AskUserQuestion|TaskStop"}` under `PreToolUse`, and a `SessionStart` entry for `session-start`.
Piece 8 (script allow) adds `batches.py` to `SCRIPTS`: main session only, a known subcommand, every argument
`plain()` or one of `--json` and `--session`.

### 3. The status mod reads the batch files

`hooks/status.mjs`:
- `summary()` drops `foreman: `, and the error note becomes `status unavailable: <reason>`; the harness already
  prefixes the plugin's status line. The band above the prompt has no prefix of its own.
- `collect()` first runs `python3 <root>/scripts/batches.py show --json --session <sid>`. With batch files, there
  is one line per batch: name, status (with round or PR), and for a batch with a PR the existing CI, bots, threads
  and merge cells. The summary reads `<n> batches · <s> spec · <v> in review · <p> passed · <r> released ·
  <m> PRs · <k> parked · <g> green`, leaving out zero counts.
- With no batch files for the session, or a failed call, it falls back to today's worktree scan.

### 4. SKILL.md changes

- **W2:**
  - The pool filter "need a human decision" is replaced by an explicit rule: "admit rows that seem to need a
    human decision; the spec phase parks them `open question` if they do".
  - The parked-row rule's stay-out reasons become `open question`, `not released by the human`, `stopped by the
    human` and `comment round failed`.
- **W3:**
  - The state-table bullet is replaced by `batches.py`. At launch: `set <b> status=spec rows=… owned=…`, `task <b> add worker fw-<b>`, `stamp <b> sent`, and the timer's `task <b> add timer <id>`.
  - Each worker's Agent `name` is `fw-<batch>`, never the bare batch name: TaskStop takes that name as its id.
  - Before the first timer: load the deferred tools with ToolSearch `select:TaskStop,Monitor`.
  - `worktree` and `branch` are set at the first `SPEC READY`, which carries them; a park before it finds the
    worktree with `git worktree list` (the one whose branch the worker created), or copies nothing.
  - Preflight also warns when a `PreToolUse` Bash hook in `~/.claude/settings.json`, `.claude/settings.json` or
    `.claude/settings.local.json` runs `rtk hook` directly, unwrapped (finding 12); a wrapper that exempts worktrees,
    per P2's recipe, is fine.
- **W3.5:**
  - **Pre-checks (step 1):** every bullet under `## Open questions` starts `- **Blocking:**` or
    `- **Non-blocking:**`, or the section reads `None — …`; anything else is a bounce (`bump <b> bounces`). A
    Blocking question parks the batch now (`reason=open-question`), before any round, at any `SPEC READY`.
  - **Dispatch (step 2):** every reviewer (chain, opus, sonnet) is recorded with `task <b> add`; Agent reviewers
    are dispatched **unnamed** (no `name`). Before each round, `set <b> status=review`. When a verdict lands,
    `task <b> verdict <id>`, TaskStop that reviewer by its id, then `task <b> done <id>`; a TaskStop of an
    already-finished task may error, which is ignored.
  - **Verdict (step 3):** after each round, `add-round … entry=<the chain log's .entry>`. A verdict that rules an open question blocking parks the
    batch right after that round (`reason=open-question`). At a pass: `set <b> status=passed reviewed_sha=<sha>`
    and `note` the Minor findings and open questions.
  - The orchestrator never edits a worker's spec. Minor findings go in the release message.
  - **Reviewer model (step 8):** `set <b> reviewer_model=<model>`.
  - **Stop without `SPEC READY` (step 5):** when the stop notification, or a refused resume, says the agent was
    stopped by the user: `stamp <b> stopped`, park `reason=stopped-by-human`, no resume. Any other stop keeps
    "resume once, then park `spec-incomplete`".
  - **Clock (step 7):** every timer is a `run_in_background` `sleep`, recorded with `task <b> add timer <id>`;
    a superseded timer is TaskStopped by id and marked done. Remaining time comes from `batches.py show <b>`.
    A comment round stamps `comment_sent`, not `sent`.
- **W3.6:**
  - **Checkpoint:** run `python3 $FOREMAN/batches.py table checkpoint <wave>`, paste its whole output as text, then
    ask. The question form is chosen per question:
    - A question that covers one batch is single-select with Release, Comment and Park (Release and Park at the
      follow-up checkpoint).
    - Two to four batches: one multi-select question.
    - More than four: split into questions of two to four batches each (5 → 3+2, 9 → 3+3+3); more than sixteen:
      a text answer.
  - A degraded batch's option description says "cross-model review fell through to <reviewer>" or "no
    cross-model review".
  - **Releasing:** release only `reviewed_sha`. Piece 11 denies `hooks.py release` at any other SHA, and nothing
    is recorded. A batch whose spec changed after its pass gets a new W3.5 round at the new SHA, which counts
    toward `spec_review_rounds`. On every path where the release message is sent (exit 0, exit 3, `spec_gate`
    disabled), `set <b> status=released released_sha=<sha>` comes right after it.
  - **A denied release:** follow the deny text (paste the checkpoint table, or run a new round at the new SHA),
    then release again.
  - **Comment round:** `stamp <b> comment_sent` (the batch leaves `passed` and its `reviewed_sha` is cleared, so it
    can't be released and the old table no longer matches). A batch that fails it parks with
    `reason=comment-failed`.
  - **Parking**, in this order (replacing today's list):
    1. `kill -TERM` the chain's pid from `<log>.pid`, then wait for the pid file with a `Monitor` until-loop
       (`until [ ! -e <log>.pid ]; do sleep 2; done`, 30 s timeout), or, without Monitor, the same loop as a
       `run_in_background` Bash call. Go on only after its exit or timeout notification; on a timeout, carry on and say so in
       the run report.
    2. `python3 $FOREMAN/hooks.py stopping <batch>`.
    3. TaskStop every live task of the batch (`batches.py show <b>`) by id, then `task <b> done` each. A TaskStop
       error for a task that already ended is ignored, and the task is still marked done.
    4. Copy the specs to `$(git rev-parse --git-common-dir)/foreman/parked/<batch>/`: the batch's spec at the last
       pinned SHA (`git -C <worktree> show <sha>:<spec path>`). When there is no `SPEC READY` yet, or that `git show`
       fails, fall back to today's union rule (working-tree and committed specs under `{{design_spec_dir}}`). Any

## Data flow

Each step writes state; the tables, the gates and the status band only read it.

| step | orchestrator action | `batches.py` write |
|---|---|---|
| W3 launch | Agent call (first line `foreman-worker: <b> spec-phase`), timer | `set <b> status=spec rows=… owned=…`; `task add worker fw-<b>`; `stamp sent`; `task add timer` |
| `SPEC READY` | pre-checks; TaskStop the worker timer | `stamp spec_ready`; `task done <timer>`; `set worktree=… branch=… spec=… sha=… [fork_base=…]`; a bounce → `bump bounces`, `stamp sent`, `task add timer`; Blocking → park `open-question` |
| round r | chain, then read-only reviewer (unnamed) | `set status=review`; `task add chain`, `task add reviewer`, `task add timer`; on the verdict `task verdict`, `add-round`, TaskStop, `task done` |
| revise | findings sent | `stamp sent`; `task add timer` |
| pass | — | `set status=passed reviewed_sha=…` (stamps `passed`); `note minors`, `note questions` |
| W3.6 manual | `table checkpoint <wave>`, pasted, then the question | the stamp; piece 11 checks it |
| comment round | comments sent as findings | `stamp comment_sent` (status `review`, `reviewed_sha` cleared); `task add timer` |
| release | `hooks.py release <b> <reviewed_sha>` (piece 11 denies any other SHA), then the message | `set status=released released_sha=<sha>` |

| W4 | verify, PR, findings, replacement worker, stop after merge | `set verified_sha=…`; `set status=pr pr=<n>`; `bump pr_rounds`; `task add worker fw-<b>-<k>`; after the merge `stopping`, TaskStop, `task done` |
| W6 stop | `table report`, pasted, then `run-end` | the stamp; piece 11 checks it |

## Error handling

- **`batches.py` failures** exit non-zero with the reason: no state dir, a bad key or token, a release at an
  unreviewed SHA, corrupt JSON. SKILL.md tells the orchestrator to fix the command and run it again; a state change
  is never dropped.
- **Every gate fails open** on its own errors: an unreadable transcript, an unreadable batch file. With no run
  marker, nothing is gated, but W3.6 and W6 still say to paste the tables.
- **The status band** falls back to the worktree scan when `batches.py` finds no files or fails.
- **Human-stop detection is conservative.** Only the stop notification or a refused resume that names the user
  counts.
- **The degraded flag** is informational and never blocks.
