# foreman 0.5.1: spec-phase fixes from the dry runs — design

Status: draft for review, revision 2 (2026-10-04). Round 1 (three opus reviewers: coverage, code consistency,
feasibility) returned 3 Critical and ~25 Important findings; this revision answers them (see Review responses).
Branch `feat/spec-phase-fixes`, stacked on `feat/spec-phase` (0.5.0, PR #3).

## Purpose

The 0.5.0 dry runs (PR #3's description, scenarios A, A′, B, C, D) found 15 problems. The spec phase worked, but
the orchestrator skipped two tables it was told to show, asked one invalid question, used blocked or misused
harness tools, and kept state only in its own context, so the status band and the tables had nothing reliable to
read. 0.5.1 fixes all 15.

The lesson behind the design: every finding that depended on the orchestrator following a prose step (show a
table, stop by id, stop in order, don't edit) was violated at least once. So each fix that can be enforced at a
tool call is enforced there, by a hook reading state on disk; prose is kept only where no tool call exists.

Success means:
- in manual mode, a checkpoint question can't be asked until the checkpoint table, for the current state, is in
  the orchestrator's visible text; and `run-end` can't run until the spec-phase report table is (hooks active);
- every batch that reaches the spec phase ends `released` or `parked` with a reason from a closed list, including
  a batch whose worker the human stopped;
- TaskStop is refused without a task id, with a batch name, and for a worker before `hooks.py stopping`;
- no foreground `sleep`, and no reviewer agent left holding a PTY after its verdict;
- workers commit in their worktrees when an RTK-style git rewrite hook is installed (decided by probe P2);
- the status band shows one prefix and counts that match the batch state;
- in `--auto-merge` (no checkpoint), a degraded review is visible in the report table.

## Decisions (from brainstorming, 2026-10-04)

- **Ambiguous rows: the spec phase owns them.** W2 stops filtering "needs a human decision" in parallel mode. A
  batch whose spec has a blocking open question parks at `SPEC READY`, before any review round.
- **Tables: state file + script + hook.** Batch state moves out of the orchestrator's context into one JSON file
  per batch, written by a new `scripts/batches.py`. The script prints the tables, and hooks refuse the checkpoint
  question and `run-end` until the matching table is in the orchestrator's visible text.
- **A human stop parks the batch** with the new reason `stopped by the human`. The worker isn't resumed or
  relaunched, and the rows stay out of later pools until the human edits the note.

## Non-goals

- Serial mode, W2's batching, W4's build-phase checks and the reviewer chain are unchanged.
- No new reviewer adapters. Codex being out of credits is an account problem; finding 14 only makes the weaker
  review visible.
- Finding 15 (bypass mode hides the missing `permissions.allow` entries) needs no change: W3 already warns on every
  run, and bypass mode is the user's choice.
- Existing configs keep their `forbid_trailers`; vacancy-vibe gets the new default in its switch-over PR.

## Components

### 1. `scripts/batches.py`: batch state on disk

The source of truth for the spec-phase tables, the hook gates and the status band. Pure Python 3 stdlib, like the
other scripts; it reads config through `cfg.py` and never calls git or gh.

**Location.** `<state dir>/batches/<session>/state/<batch>.json`. The `state/` subdirectory keeps the files out of
reach of `hooks.py forget` (which deletes `batches/<session>/<batch>.*`) so the report table at W6 still sees every
wave's batches. `prune` ages `batches/*/state/*` out after 14 days like the other batch files. Writes go to every
`state.state_dirs(main)` entry, as `mint` does, so a hook whose environment lacks a Bash-only `FOREMAN_HOME` still
reads them; reads take the first dir that has the file.

**Session.** Resolved in this order:
1. `--session <id>` (the status mod passes this).
2. `$FOREMAN_SESSION`, exported for every Bash call by a new `SessionStart` hook: `hooks.py session-start`
   appends `export FOREMAN_SESSION=<session_id>` to `$CLAUDE_ENV_FILE`, and writes nothing when it is unset.
   Probe P1 confirms the mechanism first.
3. The most recently touched live run marker in the state dirs (every hook call in a run touches its marker),
   with a stderr note naming the session when there are two or more.
4. Else `nosession`: the tables still work; the gates and the status band (which need a marker) see nothing.

**Locking.** Every read-modify-write, and every table render with its stamp, runs under an exclusive `fcntl.flock`
on `<state dir>/batches/<session>/state/.lock`. Writes are atomic (temp file in the same directory, then
`os.replace`). A file that doesn't parse as JSON is refused (exit 1, "corrupt batch state: <path>") and left
untouched.

**Argument syntax.** Every argument is one shell word with no quotes, spaces, `;` or `$`, so piece 8 can allow
the calls without a prompt. Free text (Minor findings, open questions, a park note) is read from a file with
`note`, never from the command line.

**Fields.** Unknown keys and values outside the listed tokens are refused.

| key | values |
|---|---|
| `status` | `spec`, `review`, `passed`, `released`, `pr`, `parked` (the round number comes from `rounds`, the PR number from `pr`) |
| `reason` | with `status=parked` only, one of: `open-question`, `no-pass`, `timed-out`, `spec-incomplete`, `bounces`, `review-failed`, `worker-stuck`, `not-released`, `scope-conflict`, `release-unrecorded`, `stopped-by-human`, `comment-failed` |
| `rows`, `owned` | comma-separated row ids / owned files |
| `worktree`, `branch`, `spec`, `fork_base` | paths and refs from W3 and the first `SPEC READY` |
| `sha` | the SHA the current round is pinned to |
| `reviewed_sha`, `released_sha`, `verified_sha` | at pass, at release, at W4.1 |
| `pr` | PR number |
| `reviewer_model` | W3.5 step 8's model |

Counters: `pr_rounds` (W4.4 sends after the PR opened), `bounces`. Text fields, set by `note`: `minors`,
`questions`, `park_note`. Computed, never set: `degraded`, `worker_time`, `remaining`.

Reasons render as prose in tables and W5 notes: `open-question` → "open question", `no-pass` → "no pass in <n>
rounds", `timed-out` → "spec phase timed out", `spec-incomplete` → "spec incomplete", `bounces` → "spec incomplete
after 2 bounces", `review-failed` → "review could not run", `worker-stuck` → "worker stuck", `not-released` → "not
released by the human", `scope-conflict` → "scope conflict", `release-unrecorded` → "release could not be
recorded", `stopped-by-human` → "stopped by the human", `comment-failed` → "comment round failed".

**Stamps** (epoch seconds, appended): `sent`, `comment_sent`, `spec_ready`, `stopped`. `ended` is appended
automatically when `status` becomes `released` or `parked`. Worker time is the sum of each `spec_ready` or
`stopped` minus the `sent` before it, plus `now − last sent` while working; intervals opened by `comment_sent`
are left out (W3.5's clock rule).

**Tasks.** A list of `{kind, id, live}` entries, `kind` one of `worker`, `timer`, `chain`, `reviewer`. Several of
a kind can be live at once (two reviewers in W3.5 case c, a timer per running reviewer, W4.2b's reviewer). These
ids are the only ones TaskStop is given for a batch.

**Rounds.** A list appended by `add-round`: `{r, sha, chain, fallthrough, explore, crit, imp, minor}`. `degraded`
is `yes` when the last round's `chain` is `none` or isn't the first entry of the config's `reviewers`.

**CLI.** Exit 0 on success, 1 with a one-line reason on stderr, 2 on a usage error.

| command | does |
|---|---|
| `set <batch> key=value…` | creates the file on first use; sets the keys. `status=released` is refused unless `released_sha` equals `reviewed_sha`; `status=parked` needs `reason` |
| `note <batch> minors\|questions\|park_note <file>` | sets the text field to the file's non-empty lines |
| `bump <batch> pr_rounds\|bounces` | adds one |
| `stamp <batch> sent\|comment_sent\|spec_ready\|stopped` | appends now |
| `task <batch> add <kind> <id>` / `task <batch> done <id>` | records a task / marks it not live |
| `add-round <batch> r=<n> sha=<sha> chain=<adapter\|none> [fallthrough=<adapter:why,…>] explore=<pass\|revise\|none> crit=<n> imp=<n> minor=<n>` | appends a round; sets `status=review` |
| `show [<batch>] [--json] [--session <id>]` | one batch, or every batch of the session, with the computed fields |
| `table checkpoint <wave>` | prints the W3.6 table for the wave and writes its stamp |
| `table report` | prints the W6 spec-phase table for the session and writes its stamp |

`<wave>` is a batch name minus its final letter (`20261002-1530-w1` for `20261002-1530-w1a`).

**Tables.** Both print a first line `foreman <checkpoint|report> <wave|session> <id>`, where `<id>` is the first
8 hex digits of the SHA-1 of the rendered rows, then a Markdown table.
- `table checkpoint <wave>`: batch, rows, spec path, rounds, chain reviewer (`⚠ degraded` when degraded), last
  read-only verdict, open Minor findings, open questions, status. Stamp:
  `batches/<session>/state/<wave>.shown` = `{at, id, text}`.
- `table report`: batch, spec wall-clock (first `sent` to `ended`), rounds, landed reviewer (or the fall-through,
  or `no cross-model review`), degraded, reviewer model, status and park reason, rounds after the PR. Stamp:
  `batches/<session>/state/report.shown`.

Because the id hashes the whole rendered table (status, round count, verdict, Minor findings, questions), a comment
round that ends `passed` again still changes it (scenario A′).

### 2. Hook piece 11, `batch_state`

In `scripts/hooks.py`, run-only, main session unless noted. `hooks_disabled: [batch_state]` turns it off. Every
duty fails open on its own errors (stderr note, allow), like every piece.

1. **Worker deny** (Bash, any subagent). A call that runs `batches.py` is denied: "only the orchestrator writes
   batch state". `FAST` gains `batches\.py` so the Bash pieces see the call; detection reuses `runs_control`'s
   shape, so a mention in a string or heredoc isn't a call.
2. **Checkpoint gate** (`AskUserQuestion`). It applies while any batch of this session has `status=passed` (in
   manual mode these are held for the checkpoint; in `--auto-merge` a batch is released right after it passes).
   Then every `AskUserQuestion` is checked: for each wave with a `passed` batch, the current rendered table must
   equal the stamp's `text`, and every line of it must appear (whitespace-normalised) in the assistant text blocks
   of `transcript_path` written after the stamp's `at`. A Bash tool result doesn't count: the table must be in the
   orchestrator's own text, which the human sees. Deny reasons name the fix: "run `python3 $FOREMAN/batches.py
   table checkpoint <wave>` and paste its output as text before asking" or "the table changed since it was shown;
   run it again".
   - A question whose header, question or option labels match `/releas|checkpoint/i` while the session has
     spec-phase batches and none is `passed` is denied: "no batch is passed yet; record the pass first
     (`batches.py set <b> status=passed reviewed_sha=<sha>`)".
3. **Report gate** (`hooks.py run-end`, the control call). When this session has batch files, `run-end` is denied
   until `report.shown` exists, its text equals the current rendered report, and its lines are in the assistant
   text after its `at`: "paste `python3 $FOREMAN/batches.py table report` into the run report first".
4. **TaskStop guard** (`TaskStop`). Deny when `task_id` is missing or empty; when it equals a batch name of this
   session ("TaskStop takes a task id, not a batch name; the ids are in `batches.py show <batch>`"); or when it is
   a live `worker` task of a batch with no `<batch>.stopped` record ("run `python3 $FOREMAN/hooks.py stopping
   <batch>` first"). An id no batch records is allowed: the session has other tasks.

If probe P3 shows the assistant text isn't in the transcript yet when PreToolUse fires, duties 2 and 3 fall back
to requiring the table's first line (`foreman checkpoint <wave> <id>`) in the question text, or in the assistant
text written before the `run-end` call's turn.

`pretool()` gains `AskUserQuestion` and `TaskStop` branches. `hooks/hooks.json` gains
`{"matcher": "AskUserQuestion|TaskStop"}` under `PreToolUse`, and a `SessionStart` entry for `session-start`.
Piece 8 (script allow) adds `batches.py` to `SCRIPTS`: main session only, a known subcommand, every argument
`plain()`.

### 3. The status mod reads the batch files

`hooks/status.mjs`:
- `summary()` and the error note drop `foreman: `; the harness already prefixes the plugin's status line.
- `collect()` first runs `python3 <root>/scripts/batches.py show --json --session <sid>`. With batch files, there
  is one line per batch: name, status (with round or PR), and for a batch with a PR the existing CI, bots, threads
  and merge cells. The summary reads `<n> batches · <s> spec · <v> in review · <p> passed · <r> released ·
  <m> PRs · <k> parked · <g> green`, leaving out zero counts.
- With no batch files for the session, or a failed call, it falls back to today's worktree scan.

### 4. SKILL.md changes

- **W2:**
  - The pool filter "need a human decision" is dropped in parallel mode.
  - The parked-row rule's stay-out reasons become `open question`, `not released by the human`, `stopped by the
    human` and `comment round failed`.
- **W3:**
  - The state-table bullet is replaced by `batches.py`. At launch: `set <b> status=spec rows=… owned=…
    worktree=… branch=…`, `task <b> add worker <id>`, `stamp <b> sent`, and the timer's `task <b> add timer <id>`.
  - Preflight also warns when a `PreToolUse` Bash hook in `~/.claude/settings.json`, `.claude/settings.json` or
    `.claude/settings.local.json` has a command that mentions `rtk` (finding 12).
- **W3.5:**
  - **Pre-checks (step 1):** every bullet under `## Open questions` starts `- **Blocking:**` or
    `- **Non-blocking:**`, or the section reads `None — …`; anything else is a bounce (`bump <b> bounces`). A
    Blocking question parks the batch now (`reason=open-question`), before any round, at any `SPEC READY`.
  - **Dispatch (step 2):** every reviewer (chain, opus, sonnet) is recorded with `task <b> add`; Agent reviewers
    are dispatched **unnamed** (no `name`). When a verdict lands, TaskStop that reviewer by its id and `task <b>
    done <id>`; a TaskStop of an already-finished task may error, which is ignored.
  - **Verdict (step 3):** after each round, `add-round …`. A verdict that rules an open question blocking parks the
    batch right after that round (`reason=open-question`). At a pass: `set <b> status=passed reviewed_sha=<sha>`
    and `note` the Minor findings and open questions.
  - The orchestrator never edits a worker's spec. Minor findings go in the release message.
  - **Stop without `SPEC READY` (step 5):** when the stop notification, or a refused resume, says the agent was
    stopped by the user: `stamp <b> stopped`, park `reason=stopped-by-human`, no resume. Any other stop keeps
    "resume once, then park `spec-incomplete`".
  - **Clock (step 7):** every timer is a `run_in_background` `sleep`, recorded with `task <b> add timer <id>`;
    a superseded timer is TaskStopped by id and marked done. Remaining time comes from `batches.py show <b>`.
    A comment round stamps `comment_sent`, not `sent`.
- **W3.6:**
  - **Checkpoint:** run `python3 $FOREMAN/batches.py table checkpoint <wave>`, paste its whole output as text, then
    ask. The question form is chosen per question:
    - A question that covers one batch is single-select with Release, Comment and Park (Release and Park at the
      follow-up checkpoint).
    - Two to four batches: one multi-select question.
    - More than four: split into questions of two to four batches each (5 → 3+2, 9 → 3+3+3); more than sixteen:
      a text answer.
  - A degraded batch's option description says "cross-model review fell through to <reviewer>" or "no
    cross-model review".
  - **Releasing:** after `hooks.py release` succeeds, `set <b> status=released released_sha=<sha>` (refused unless it
    is the reviewed SHA).
  - **Comment round:** a batch that fails it parks with `reason=comment-failed`.
  - **Parking**, in this order:
    1. `kill -TERM` the chain's pid from `<log>.pid`, then wait for the pid file with a `Monitor` until-loop
       (`until [ ! -e <log>.pid ]; do sleep 2; done`, 30 s timeout).
    2. `python3 $FOREMAN/hooks.py stopping <batch>`.
    3. TaskStop every live task of the batch (`batches.py show <b>`) by id, then `task <b> done` each.
    4. Copy the spec at the last pinned SHA (`git -C <worktree> show <sha>:<spec path>`); only a batch with no
       `SPEC READY` yet copies from the working tree.
    5. `note <b> park_note <file>` and `set <b> status=parked reason=<reason>`.
- **W4:**
  - On the PR: `set <b> status=pr pr=<n>`; each W4.4 send is `bump <b> pr_rounds`; a replacement worker is
    `task <b> add worker <id>`.
  - **W4.2b and the deviation-round reviewer** follow W3.5's dispatch rule: unnamed, recorded, stopped by id when the
    verdict lands. An environment failure (`fork failed`, `Device not configured`) gets one more try after
    TaskStopping every recorded reviewer task of the session whose verdict has landed. This retry is not the one
    re-dispatch, and it never stops a `worker` task.
- **W5:** `hooks.py forget` is unchanged and no longer touches batch state.
- **W6:**
  - The stuck-worker rule: `stopping`, then TaskStop of the recorded `worker` id.
  - **Run report:** run `python3 $FOREMAN/batches.py table report`, paste its whole output as the spec-phase table,
    then `run-end` (piece 11 refuses `run-end` until the table is pasted).
- **Worker contract and Worker spec phase:**
  - Git commands follow probe P2's outcome (Testing).
  - New Worker spec phase line: label every open question `- **Blocking:**` (the batch can't be built as specified
    without the answer) or `- **Non-blocking:**`. On a Blocking one, finish the spec and report `SPEC READY` at
    once.
- **Hooks section:** the piece 11 row: `batch_state`, run-only, worker deny, checkpoint gate, report gate and
  TaskStop guard.

## Data flow

Each step writes state; the tables, the gates and the status band only read it.

| step | orchestrator action | `batches.py` write |
|---|---|---|
| W3 launch | Agent call (first line `foreman-worker: <b> spec-phase`), timer | `set <b> status=spec rows=… owned=… worktree=… branch=…`; `task add worker`; `stamp sent`; `task add timer` |
| `SPEC READY` | pre-checks | `stamp spec_ready`; `set spec=… sha=… [fork_base=…]`; a bounce → `bump bounces`, `stamp sent`; Blocking → park `open-question` |
| round r | chain, then read-only reviewer (unnamed) | `task add chain`, `task add reviewer`, `task add timer`; on the verdict `add-round`, TaskStop, `task done` |
| revise | findings sent | `stamp sent`; `task add timer` |
| pass | — | `set status=passed reviewed_sha=…`; `note minors`, `note questions` |
| W3.6 manual | `table checkpoint <wave>`, pasted, then the question | the stamp; piece 11 checks it |
| comment round | comments sent as findings | `stamp comment_sent`; `task add timer` |
| release | `hooks.py release <b> <sha>`, then the message | `set status=released released_sha=<sha>` |
| park | kill, `stopping`, TaskStop by id, copy at the pinned SHA | `task done …`; `note park_note`; `set status=parked reason=…` |
| human stop | the stop notification, or a refused resume naming the user | `stamp stopped`; park `stopped-by-human` |
| W4 | PR, findings, replacement worker | `set status=pr pr=<n>`; `bump pr_rounds`; `task add worker` |
| W6 stop | `table report`, pasted, then `run-end` | the stamp; piece 11 checks it |

## Error handling

- **`batches.py` failures** exit non-zero with the reason: no state dir, a bad key or token, a release at an
  unreviewed SHA, corrupt JSON. SKILL.md tells the orchestrator to fix the command and run it again; a state change
  is never dropped.
- **Every gate fails open** on its own errors: an unreadable transcript, an unreadable batch file. With no run
  marker, nothing is gated, but W3.6 and W6 still say to paste the tables.
- **The status band** falls back to the worktree scan when `batches.py` finds no files or fails.
- **Human-stop detection is conservative.** Only the stop notification or a refused resume that names the user
  counts.
- **The degraded flag** is informational and never blocks.
